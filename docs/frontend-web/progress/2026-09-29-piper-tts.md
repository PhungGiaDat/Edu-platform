# Piper TTS delivery — 2026-09-29

Status: CODE_VERIFIED and RUNTIME_VERIFIED on the deployed backend and responsive production web app. Physical-device browser testing and VPS resource/load profiling remain unverified.

## Delivered behavior

- Source commit: `9cd769d4b27598616b4d9eed6115d7617e25b587`, branch `10-days-quick-run`.
- Existing FastAPI TTS service now uses CPU Piper 1.8.0 for English (`en_US-lessac-medium`) and Vietnamese (`vi_VN-vais1000-medium`). Locale forms such as `en-US` and `vi-VN` normalize to the corresponding model.
- Native model sessions are reused, with two CPU threads and serialized synthesis; work runs outside the async event loop. No separate TTS service or GPU is required.
- WAV cache keys include voice/model identity and speed. Cache reads validate PCM payload and derive duration/sample rate from the actual WAV. Writes replace atomically; cache-write failure does not discard usable generated audio.
- Existing GET/POST contracts and authored vocabulary audio remain in use. English/Vietnamese Piper playback requires no cloud TTS credentials or per-request cloud TTS payment.
- Docker image downloads both voices during build, checks four pinned SHA256 hashes, and synthesizes real English/Vietnamese WAVs before publication. Production runs as the existing non-root application user.
