# Deployment Preparation and Rollback Plan

Status: prepared, not executed

Approval required: production backend deploy, frontend deploy, credential rotation and Mongo apply

## Required order

1. Create a release candidate from `codex/sdlc-profile-navigation-fixes`; do not merge the unrelated local `main` commit.
2. Deploy backend to staging.
3. Verify OpenAPI exposes `UserResponse.is_superuser`, `role`, `roles`, `full_name`, `avatar_url`, and `GET /api/v1/profile/me`.
4. Run staging auth/profile smoke tests with a learner and a disposable elevated account.
5. Deploy frontend to staging and complete the viewport matrix in the test report.
6. Deploy backend to production first and verify health/OpenAPI.
7. Deploy frontend to production; log out/in once to replace stale stored auth data.
8. Set `ADMIN_EMAIL`, `ADMIN_USERNAME`, and a newly rotated `ADMIN_PASSWORD`; run the admin script without `--apply`, review, then explicitly apply/reset.
9. Run the Momo Mongo migration without flags. Review course IDs and field counts, then run `--apply --confirm momo-unicode-v1` only with approval.
10. Verify `/admin`, `/profile`, course catalog Unicode, navigation breakpoints and Lexi in production.

## Commands (backend directory)

```powershell
python scripts/create_admin.py
python scripts/create_admin.py --apply --reset-password

python -m database.migrations.repair_momo_course_unicode
python -m database.migrations.repair_momo_course_unicode --apply --confirm momo-unicode-v1
```

Do not place credentials in command history; provide them through the deployment platform environment.

## Rollback

- Frontend: promote the previous Vercel deployment.
- Backend: roll Render back to the previous known-good commit. The extra response fields and endpoint are additive.
- Admin privilege: inspect the backed-up/previous user state before changing role flags; do not restore the disclosed password.
- Course data: locate `course_migration_backups` by the printed `run_id` and restore only the three original documents after validating course IDs. Do not run a blind collection replacement.
- Profile content: the lazily inserted `profile_content` document is additive and can remain; remove it only if a reviewed rollback requires it.

## Go/no-go gate

No-go if backend schema is stale, any automated check fails, staging has horizontal overflow, learner access reaches admin APIs, migration dry-run targets an unexpected course/field, or backups cannot be confirmed.
