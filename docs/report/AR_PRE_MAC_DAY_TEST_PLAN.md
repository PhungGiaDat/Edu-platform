# AR Pre-Mac-Day Test Plan

**Goal:** Validate the full RN ↔ Unity AR pipeline in the Windows Editor BEFORE
spending Mac Day on a build. Catch integration bugs early so Mac Day is just
"open in Xcode → archive → install on phone", not "fix 12 silent errors".

**Strategy:** Mock the AR subsystem inside the Editor. Real ARKit needs macOS,
but we can drive `ARTrackedImageManager.trackablesChanged` ourselves with
synthetic events. Every other downstream consumer
(`ARSessionManager.HandleTrackedImagesChanged`, `ARExperienceHandler.HandleImageDetected`,
`RNEventEmitter`) runs unchanged against real input shape — which is exactly
what we want to verify.

## What's covered

| Component                          | Verification path                                              |
| ---------------------------------- | -------------------------------------------------------------- |
| `RNMessageReceiver.OnMessageFromRN` | `ARTestHarness` + `ManualRegressionRunner` synthesize calls.   |
| `ARPayloadMapper` (JSON parsing)   | Test harness sends real JSON-shaped payloads.                  |
| `ARSessionManager` (event handler) | Same path as production; defensive null-check added.           |
| `ARExperienceHandler`              | Fires when `loadARExperience` + detection complete.            |
| `RNEventEmitter`                   | Logs every `SendEvent` call with the payload name → easy to grep. |
| `GLBLoader`                        | Skipped by default (URL unreachable from CI).                  |
| `ARAudioPlayer`                    | Skipped by default (same reason).                              |
| `AnchorManager` / `ARGestureHandler` | Not exercised in F9 regression; tested on device.            |

## How to run

### Editor (Windows)

1. Open the project in Unity 6000.3.20f1.
2. Open scene `Assets/Scenes/ARTestScene.unity`.
3. Press **Play**.
4. Watch the Console for `[POCBootstrap]` + `[ARTestHarness]` lines.

### Modes

- **Auto-run on Play:** `ARTestRunner.runMockTestOnStart = true` (Inspector) → after 2s, fires a synthetic detection.
- **Manual hotkeys:** `EditorMockImageDetector` prints its hotkeys on startup:
  - `Space` → simulate image detected
  - `T`     → simulate tracking lost
  - `R`     → re-spawn (lost + detected)
  - `Esc`   → stop play mode
- **Full pipeline regression:** press **F9** (handled by `ManualRegressionRunner`) → runs all 9 steps + summary.

## Mac Day checklist

Carry this page to the Mac on Day 13 (2026-08-07). If the Editor test passes,
your only unknowns on Mac are Xcode toolchain and iOS-specific runtime quirks.

| Step                          | Pass criterion                                                              |
| ----------------------------- | --------------------------------------------------------------------------- |
| Open Xcode project            | Project generated by `POCBuildScript.BuildIOS` opens without schema errors. |
| Select dev team              | Signing & Capabilities → Team = (your Apple ID).                            |
| Plug in iPhone                | Xcode Devices window shows it; no "untrusted developer" prompt appears.     |
| Build (cmd+B)                 | Compiles clean. ARFoundation + ARKit frameworks embed.                      |
| Run (cmd+R)                   | App launches, lands on Home screen.                                        |
| Tap "Start AR"                | Camera permission prompt → Allow.                                           |
| `initSession` event           | RN console: `[Unity] onArReady`. iPhone console: `[ARSessionManager] State: Ready`. |
| `loadARExperience`            | RN posts payload; Unity logs `[ARExperienceHandler] LoadARExperience called`. |
| Scan elephant printout        | `RuntimeImageTrackingPOC` status overlay shows "DETECTED".                  |
| Model spawns                  | A 3D object appears over the printed image.                                 |
| Audio plays                   | Hear audio clip.                                                            |
| Background app                | `pauseSession` event fires (verify via Debug overlay or RN log).            |
| Foreground app                | `resumeSession` event fires.                                                |
| Multi-target (2 printouts)    | `onMultiImageDetected` event with `count >= 2`.                            |

## Known limitations

- **Camera background** in Editor is black, not live AR feed. Visual tracking is verified via `RuntimeImageTrackingPOC` status overlay text only.
- **Reflection-based mocks** in `EditorMockImageDetector` may break on future
  Unity versions that change `ARTrackedImage`'s internal members. If that
  happens, the test will log `ARTrackedImageManager.OnTrackablesChanged not
  found via reflection` and steps 4 + 10 will fail. Re-test with real device.

## Out of scope (for device testing only)

- Gesture handler (tap/drag/pinch → requires touch on device)
- Plane detection visuals (requires real camera)
- GLB / Audio download from real network
- Frame-rate / thermal behavior
