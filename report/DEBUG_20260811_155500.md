# Debug Report

## Issue Summary
**Description:** `[runtime not ready]: Error: Exception in HostFunction: <unknown>` — iOS bundling completes (36296ms, 1315 modules) but the app crashes before rendering.
**Severity:** High
**Status:** Diagnosed

## Reproduction Steps
1. Run `expo start --ios` or `npx expo run:ios` in `mobile/rn/`
2. Wait for Metro bundler to complete iOS build (36296ms, 1315 modules)
3. App crashes with `[runtime not ready]` error before the auth screen renders

## Evidence

### Error Message
```
ERROR  [runtime not ready]: Error: Exception in HostFunction: <unknown>
```

The error appears **after** bundling completes (36296ms with 1315 modules), which means:
- All JS code was bundled successfully (no syntax/transpilation errors)
- The error occurs at **runtime** when React Native tries to execute native module calls
- The error specifically mentions `HostFunction`, which is RN's bridge mechanism for calling native code from JS

### Root Cause

**Primary Issue: Missing `babel.config.js` with Reanimated Plugin**

The project uses `react-native-reanimated@4.1.1` but has **no `babel.config.js`** file in `mobile/rn/`.

Reanimated 4.x requires the `react-native-reanimated/plugin` to be registered in Babel. Without it:
- Reanimated's worklet functions (`useSharedValue`, `useAnimatedStyle`, `withSpring`, etc.) are treated as **regular JavaScript**, not worklets
- When these worklets are executed at runtime, they attempt to call native host functions that don't exist in the expected context
- This triggers the `[runtime not ready]` error because Reanimated's native bridge is not initialized

**Why bundling succeeds:** Metro can transpile and bundle all the JS/TS code. The crash only happens at runtime when the JS engine tries to execute worklet code against the native runtime without proper initialization.

### Missing Babel Config Evidence

There is no `babel.config.js` or `babel.config.cjs` in `mobile/rn/`:
```bash
$ ls mobile/rn/ | grep babel
# (nothing)
```

`babel-preset-expo` is installed (package-lock.json line 4353) but without an explicit `babel.config.js`, the Reanimated plugin is not applied.

### Secondary Issue: `ClayButton.tsx` Dynamic Require Pattern

`src/components/ClayButton.tsx` lines 26-29 use a module-level dynamic require:

```typescript
const AnimatedTouchable = Animated.createAnimatedComponent(
  // eslint-disable-next-line @typescript-eslint/no-explicit-any
  require('react-native').TouchableOpacity as any
);
```

While this works in development, it could cause issues in production builds where module loading order differs. This is a **secondary concern** but should be addressed.

## Files Requiring Fixes

### 1. `mobile/rn/babel.config.js` — CREATE THIS FILE

**Lines:** N/A (new file)

**Content:**
```javascript
module.exports = function (api) {
  api.cache(true);
  return {
    presets: ['babel-preset-expo'],
    plugins: ['react-native-reanimated/plugin'],
  };
};
```

**Rationale:** This is the **primary fix**. The `react-native-reanimated/plugin` must be the **last plugin** in the plugins array. This plugin:
- Transforms worklet functions into code that can run on the UI thread
- Registers the native Reanimated runtime before the app starts
- Enables `useSharedValue`, `useAnimatedStyle`, `withSpring`, etc. to work correctly

### 2. `mobile/rn/src/components/ClayButton.tsx` — REFACTOR Dynamic Require

**Lines:** 26-29

**Current:**
```typescript
const AnimatedTouchable = Animated.createAnimatedComponent(
  // eslint-disable-next-line @typescript-eslint/no-explicit-any
  require('react-native').TouchableOpacity as any
);
```

**Fix — use static import:**
```typescript
import { TouchableOpacity } from 'react-native';
import Animated, {
  useSharedValue,
  useAnimatedStyle,
  withSpring,
} from 'react-native-reanimated';

const AnimatedTouchable = Animated.createAnimatedComponent(TouchableOpacity);
```

Then remove the unused TouchableOpacity import from line 2's import statement.

**Rationale:** Static imports are more reliable across React Native versions and build configurations. Dynamic `require()` at module level can cause initialization order issues.

## Why Not Unity Bridge?

The `UnityBridgeModule.ts` is a Phase 1 placeholder with proper null checks (`if (UnityBridge)`). It would NOT cause this error because:
- It gracefully handles missing native modules
- No code path calls `UnityBridge` without checking availability first

## Why Not Expo Modules?

`expo-secure-store`, `expo-linear-gradient`, `expo-av` are all properly initialized by Expo's autolinking. They don't cause `[runtime not ready]` errors.

## Recommended Fix Priority

1. **CRITICAL — Add `babel.config.js`** with `react-native-reanimated/plugin`
2. **IMPORTANT — Refactor `ClayButton.tsx`** to use static imports

## Verification Steps
